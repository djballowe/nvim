# AGENTS.md

Guidance for coding agents working in this repository.

## Repository overview

This is a personal Neovim configuration derived from kickstart.nvim. The configuration is written in Lua, uses lazy.nvim for plugin management, and pins plugin revisions in `lazy-lock.json`.

Keep changes focused on the requested behavior. Existing options and keymaps are personal preferences; preserve them unless the task specifically calls for changing them.

The supported baseline is Neovim 0.12.0. Prefer current 0.12 APIs and validate with the latest stable 0.12 patch release; do not add compatibility shims for older Neovim releases unless requested.

## Layout and load order

`init.lua` is deliberately small. It sets the leader keys and disables netrw before any plugin can load, then requires these modules in order:

1. `lua/config/options.lua` defines editor options.
2. `lua/config/keymaps.lua` defines global keymaps.
3. `lua/config/autocmds.lua` defines general autocommands.
4. `lua/config/lazy.lua` bootstraps lazy.nvim and imports plugin specs.

All active plugin specs live under `lua/plugins/` and are automatically imported by lazy.nvim. Keep plugin-specific mappings and configuration in the relevant plugin module. The files are grouped by feature area rather than by plugin manager mechanics.

`lazy-lock.json` is generated by lazy.nvim. Do not edit it by hand, and only include lockfile changes when dependency revisions were intentionally updated.

## Where to make changes

- Add or configure plugins under `lua/plugins/`; no additional import is needed for a new module in that directory.
- Add LSP servers or server-specific settings to the `servers` table in `lua/plugins/lsp.lua`. Mason derives its install list from this table. The currently configured servers are `bashls` and `lua_ls`.
- Change Treesitter parsers in the `parsers` list in `lua/plugins/treesitter.lua`.
- Change filetype-to-formatter mappings in `lua/plugins/formatting.lua`. The manual Conform mapping is `<leader>mp`.
- Put global keymaps in `lua/config/keymaps.lua`, editor options in `lua/config/options.lua`, and general autocommands in `lua/config/autocmds.lua`.

Avoid references to fixed line numbers in documentation because this configuration changes frequently. Refer to modules, functions, or table names instead.

## Style and validation

Use StyLua for Lua formatting:

```bash
stylua --check .
```

Use `stylua <changed-lua-files>` to format edited Lua files. `.stylua.toml` is authoritative: it currently specifies a 160-column width, 2-space indentation, Unix line endings, single quotes when possible, and omitted call parentheses when possible. These source-formatting rules are separate from Neovim's 4-space editing defaults in `lua/config/options.lua`.

There is no automated test suite. When Neovim and the pinned plugins are already installed, use this as a startup smoke test after configuration changes:

```bash
nvim --headless --cmd 'set runtimepath^=.' -u init.lua '+qa'
```

Do not treat a missing external program as a Lua regression without checking the dependency first. Some features require executables such as `git`, `make`, `rg`, language servers, Treesitter compilers, or the formatters named in the Conform configuration.

## User-facing behavior worth preserving

- `:LiveGrepGitRoot` searches from the current buffer's Git root and falls back to Neovim's working directory outside a repository.
- `:Format` is buffer-local and exists only after an LSP client attaches.
- `<leader>mp` formats through Conform with LSP fallback.
- The leader and local leader are both Space and must be assigned before mappings and plugin setup run.
- netrw must be disabled before lazy.nvim loads because nvim-tree replaces it.
