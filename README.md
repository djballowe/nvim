# Neovim configuration

My personal Neovim configuration, originally derived from [kickstart.nvim](https://github.com/nvim-lua/kickstart.nvim).

The configuration targets Neovim 0.12 and tracks plugin revisions in `lazy-lock.json` for reproducible installs.

## Requirements

- Neovim 0.12.0 or newer. Use the latest stable 0.12 patch release.
- Git, for lazy.nvim bootstrapping and plugin installation.
- [ripgrep](https://github.com/BurntSushi/ripgrep), for Telescope live grep; `fd` is optional for additional Telescope functionality.
- A C compiler and Tree-sitter CLI 0.26.1 or newer, installed through a package manager rather than npm, for Treesitter parsers.
- `curl` and `tar`, for Treesitter parser downloads.
- `make`, optionally, to build Telescope's native FZF sorter.
- The external tools needed by features you use, such as language servers installed through Mason and the formatters configured in Conform.

## Install

Back up any existing Neovim configuration, then clone this repository:

```bash
git clone https://github.com/djballowe/nvim.git ~/.config/nvim
nvim
```

lazy.nvim bootstraps itself on first start. Mason installs the configured `bashls` and `lua_ls` language servers, and Treesitter installs the configured parsers.

## Structure

- `init.lua` sets globals that must exist before plugins load, then loads the configuration modules.
- `lua/config/options.lua` contains editor options.
- `lua/config/keymaps.lua` contains global, non-plugin keymaps.
- `lua/config/autocmds.lua` contains general autocommands.
- `lua/config/lazy.lua` bootstraps lazy.nvim and imports every spec under `lua/plugins/`.
- `lua/plugins/` contains one focused plugin-spec module per feature area.
- `lazy-lock.json` is generated by lazy.nvim and pins plugin revisions.

## Useful behavior

- Leader and local leader are both Space.
- `<leader>pv` toggles nvim-tree; `<leader>f` locates the current file in it.
- `<leader>pf` searches files and `<leader>sg` searches text with Telescope.
- `:LiveGrepGitRoot` searches from the current buffer's Git root and falls back to the working directory outside a repository.
- `<leader>mp` formats the current file or selection through Conform with LSP fallback.
- `:Format` is available in buffers with an attached LSP client.
- `gc` uses Neovim's commenting support, enhanced by ts-comments for embedded languages.

## Updating and validation

Use `:Lazy check` to inspect available plugin updates and `:Lazy update` to apply them. Commit `lazy-lock.json` only when those revision changes are intentional.

After changing Lua files, run:

```bash
stylua --check .
nvim --headless --cmd 'set runtimepath^=.' -u init.lua '+qa'
```

Inside Neovim, `:checkhealth` reports missing optional executables and provider issues.
